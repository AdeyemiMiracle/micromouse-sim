Adaptations for 16×16 (all shown in the source comments). Cell pitch 168 mm → 180 mm and goal = the four centre cells (7,7)(7,8)(8,7)(8,8); lone-wall standoff 50 mm → 84 mm (half corridor); side-wall threshold 90 mm → 120 mm (a centred car reads 84 mm, so 90 mm cannot absorb a post-turn offset, and an open side always reads "no echo" at 264 mm); turn stop tolerance 5° → 2°; wall-trim clamp 40 PWM → 8 PWM (40 PWM slews this chassis ~100°/s and over-rotates a cell); front-abort disarm 60 mm → 100 mm; 90° turns drive both wheels (centre pivot) instead of the firmware's single-wheel pivot, which swings the chassis ~45 mm off the corridor every turn; phase watchdog 90 s → 600 s (a 256-cell sweep takes ~9 min of simulated time); ff_updateYawSetpoint() (declared in the floodfill module, unused in the firmware) re-aligns the heading after each segment, and an aborted segment is unwound on the encoders so the next wall read still belongs to a cell.

Two run strategies (selectable in the controls). Full-map exploration sweeps every reachable cell, returns to the start cell and then sprints — the slowest option, but the sprint is planned from a complete map, so its route is the true shortest path. Goal-first (reach goal, then optimise) is the shortcut used by many teams: the car does not map the whole maze. It first drives at the centre, flooding optimistically (unknown cells treated as open) and re-planning whenever a wall turns up. Reaching the centre does not end the exploration — the corridors it came in on are rarely the fastest ones — so it keeps sweeping the unexplored cells that could still shorten the route, starting with the goal's own surroundings and working outward, and stops only when no unknown cell can beat the route it already knows (the optimistic d(start,r) + d(r,goal) test, capped at 120 extra cells). Only then does it return to the start cell, by the shortest route in its — by now much richer — map, which is usually a different route from the way in, and finally sprint the best route it knows. The route is optimal only for what is known, so it can be a few cells longer than the true optimum. The stats panel shows both: cells explored (centre → sprint) and sprint moves / optimal.
